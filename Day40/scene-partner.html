System Prompt Design

The assistant is scoped narrowly to one job: write screenplay-formatted dialogue on demand. Key design choices:

  • Role lock: the model is told it's a working screenwriter, not an assistant/chatbot — this keeps replies terse and craft-focused instead of conversational padding ("Great question! Here's some dialogue...").
  • Strict output contract: every scene reply must be valid screenplay format (SLUGLINE, CHARACTER NAME, parentheticals, action lines) so the frontend can reliably style it — that contract is enforced with explicit formatting tags the app parses into styled blocks.
  • One-line coach note: after each scene beat, the model adds a single blunt tip (why the line works, or a craft note) — capped at one sentence so it never overwhelms the dialogue itself.
  • Edge cases handled: vague/empty scene setup → model invents a plausible one instead of asking clarifying questions (keeps momentum for hobbyist users); requests to abandon screenplay format → model politely redirects back to script format; off-topic requests → model stays in character as a screenwriter and declines briefly.
  • Statelessness workaround: since the Claude API is stateless, the full scene-so-far is resent as conversation history on every call so the model can continue the same characters/scene coherently.

UI Decisions

  • Screenplay-styled output: dialogue renders in a monospace "script page" block with color-coded slugs, character names, and parentheticals, so it visually reads like an actual script excerpt rather than chat bubbles.
  • Sidebar as scene setup, not settings: most tools bury inputs behind a chat message; here structured fields (characters, situation, genre, length chips) reduce typing friction for hobbyists who want to jump straight to generation.
  • Coach notes visually separated: a thin accent-bordered callout distinguishes "craft commentary" from the dialogue itself, so the two never blur together.
  • Dark, film-set palette: warm amber accent against near-black evokes a writers'-room / editing-bay feel appropriate to screenwriting, distinct from generic blue SaaS UI.

Future Extension Ideas

  • Tools: a "read scene aloud" tool using speech synthesis per character voice; a PDF/Final Draft (.fdx) export tool.
  • Memory: persist character bibles (voice, backstory, verbal tics) across sessions so recurring characters stay consistent scene to scene.
  • Multi-step workflows: a "full scene builder" mode that first asks for beat-by-beat outline, then generates dialogue beat by beat with revision loops between each.
  • Multi-character scenes: extend beyond two characters with dynamic character slots and group blocking notes.
